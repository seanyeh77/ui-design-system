# Tour

第一次使用的導覽：一次介紹一個地方，整頁變暗，只亮出要介紹的地方。

- 亮出的地方加 3 px 強調色框；說明卡放在它下方（放不下時換到上方），寬 320 px，寫「1 / 3」、標題和一兩句說明（說明裡的反引號會變成行內程式碼）。
- 說明卡一定完整留在視窗內，四邊至少留 `--space-3`（12 px）。
- 說明卡的位置依序試：目標下方、上方、右側、左側（`side: 'top'` 時上方先試），選第一個放得進視窗、而且不蓋住目標的位置。說明裡講到的旁邊內容（例如目標下方的表格）用 `keepVisible` 指定（寫法和 `target` 一樣，可以給陣列），說明卡也不蓋住它們。四個位置都不行時，先捲動頁面騰出位置：目標加說明卡放得進視窗時，目標捲到視窗頂端、說明卡放在下方；目標比這更高時，目標的頂端捲到說明卡下方，說明卡放在目標上方。頁面捲不動時，選蓋住目標面積最小的位置，其次是蓋住 `keepVisible` 最少的位置。
- 說明卡比視窗高時（手機上的長說明），說明文字在卡片內捲動，按鈕列固定在底部。
- 目標在視窗外時先捲動到看得見：比視窗矮的捲到中間，比視窗高的從頂端開始顯示。直接跳到位置，不用平滑捲動（整頁變暗時頁面捲動被鎖住，平滑捲動會停在半路），亮框本身的 300 ms 移動就是動畫。
- 手機（小於 600 px）：目標捲到頂部列（`AppShell` 的 `.ui-shell-top`）正下方，說明卡放在目標下方、底部分頁（`.ui-tabbar`）上方，兩條列都不會被蓋住。目標加說明卡放不下時，照上面的規則捲到說明卡放在目標上方，仍在頂部列下方、底部分頁上方。目標就是底部分頁時，說明卡在它上方。
- 按鈕：左邊「略過」，右邊「上一步」和主要按鈕「下一步」，最後一步是「完成」。按 Esc 等於略過。導覽進行時頁面不能操作。
- 用 `UI.useTour(key)` 記住這個瀏覽器看過了沒有：沒看過會自動打開，看完或略過後不再出現。
- 頁面上要有「重看導覽」（例如說明選單或頁面底部的連結），呼叫 `tour.start()`。
- `target` 最好用名稱：在要介紹的元素上加 `data-tour="tree"`，`target` 寫 `'tree'`。TopBar 的搜尋框和手機的搜尋圖示都已經有 `data-tour="search"`，會用看得到的那一個。也可以給 CSS selector、ref 或元素。找不到時說明卡放在畫面中間。
- 目標要小：指向要介紹的那張卡片或那一列，不要指向整頁。目標比視窗的 70 % 高時，說明卡沒有地方放，只能蓋住目標的一部分；開發時 console 會警告。
- 步數顯示「1 / 5」（由 CSS 畫出），頁面文字和螢幕閱讀器都是「第 1 步，共 5 步」，不念「斜線」。
- 步驟最多 3 到 5 步，只介紹第一次看不出用法的地方。

```js
const tour = UI.useTour('codemap-flow');
h(UI.Tour, {
  open: tour.open, onClose: tour.close,
  steps: [
    { target: 'search', title: '搜尋', text: '搜尋函式、檔案、元件與環境變數。快捷鍵 Ctrl K。' },
    { target: 'tree', title: '流程樹', text: '名稱旁的標籤是關係的來源，點選問號查看依據。' },
    { target: 'notes', title: '檢查筆記', text: '錯誤的位置附有修正建議，可直接複製。' }
  ]
}),
h('section', { 'data-tour': 'tree' }, …),
h('button', { className: 'ui-link-btn', onClick: tour.start }, '重看導覽')
```

## 無障礙

- 「1 / 5」念成「第 1 步，共 5 步」。
- 按「下一步」或「上一步」後，live region 念出新的一步：「第 2 步，共 5 步。標題。說明。」（焦點留在按鈕上，按鈕本身不會念這些）。
- 導覽開著時焦點鎖在卡片內：Tab 和 Shift + Tab 只在「略過」「上一步」「下一步」之間循環，不會跑到頁面上（例如「跳到主要內容」）；焦點被點到卡片外時回到「下一步」。
- 按「完成」「略過」或 Escape 後，焦點回到打開導覽前所在的元素；那個元素已經不在時，移到內容（`focusMain()`）。有關閉動畫或電腦比較慢時也一樣。
